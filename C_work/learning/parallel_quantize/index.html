动画与真实硬件的对应关系 / 代码来源
页面默认暂停，可自由点击章节，也可播放完整讲解。4 通道视图是为教学缩小的例子；工程参数为 LANES=16。示例数字是可修改的教学输入，不是仿真抓取的数据。
  • 量化规则来自项目函数：对累加器原始整数除以 256，就近取整，正负半值都向远离零的方向舍入，再限制到 −32768～32767。这些数字是定点数据的整数编码；输出所表示的实数还要除以 256。
  • 动画中的流动、高亮和逐项计数是阅读顺序，不是硬件时钟周期。generate 会展开硬件；always @* 中的 for 描述组合求和，不会自动变成每拍加一个的计数器。组合逻辑仍有实际传播延迟。
  • product → accumulator → output_buffer 的寄存、偏置加载、valid/last 的传递，来自模块后面的 always_ff；用户贴出的声明本身不执行这些动作。
  • saturation_increment 是当前一组的饱和数量。工程只在 S_ROUND 时把它加到 saturation_count，并把低 16 位保存到 output_buffer。
