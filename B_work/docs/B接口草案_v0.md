# B 接口说明 v1：A 运算已适配，C 平台待对接

2026-10-19。按共同仓库 A_work 的已实现数值契约进行联合适配；**团队接口签收和正式 C 平台仍待完成，不能当作官方平台协议**。文件名保留，便于已有引用继续使用。

## 1. 已实现的边界

- B 交付 `linear_ctrl.sv`、`tensor_buffer.sv`、`sram_wrapper.sv`、`linear_accel_top.sv`。
- 新增 `a_compute_adapter.sv`、`linear_accel_a_top.sv`，实例化 A 的 `compute_lane`；A 的三份运算源码从共享仓库 A_work 引入，保持原样。
- `dot_mac_model.sv` 仍仅用于原 B 合成回归，联合测试运行真实 A RTL。
- C 接收张量和元素序号，转换为真实基地址、字节打包及总线事务；`tensor_bus_model.sv` 仅为测试端。
- B RTL 中没有矩阵乘法、量化、物理地址计算、CSR 或 CPU 软件实现。它负责供数与控制。

## 2. 联合顶层参数与数值格式

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| ROWS / INNER / COLS | 99 / 64 / 256 | 正式矩阵形状；调试可缩小行列 |
| DATA_W | 16 | X/W 的编码宽度，两者暂相同 |
| BIAS_W | 40 | 偏置编码宽度 |
| RESULT_W | 16 | A舍入、饱和后的输出编码宽度 |
| BUS_W | 64 | B/C 逻辑接口载荷宽度，与实际总线位宽无关 |

联合顶层只开放 ROWS、COLS、BUS_W 参数；INNER=64、DATA_W=16、BIAS_W=40、RESULT_W=16 固定为 A 的契约。原 `linear_accel_top` 保留可配置参数，其默认40位结果供旧合成回归使用。

B 搬运原始编码，不做量化算术。A 使用signed16乘积、signed40点积、signed41偏置加法，再按shift最近舍入（半值远离零）并饱和到signed16。bias已对齐到乘积尺度。每层 `formats.json` 提供 fx/fw/fy/shift，真实值=编码×2^(-f)，shift=fx+fw-fy。当前数据层编号2的shift=17，其余为16；由 C/测试入口传入，B不会按层编号猜测。

## 3. 时钟、任务和状态

所有接口同一 `clk` 域，`rst_n` 低有效异步复位。C 的访存适配和 A 运算端应与 B 协同复位/清空，防止复位前响应进入新任务；本原型无跨时钟逻辑。

| 端口 | 方向（相对 B） | 规则 |
| --- | --- | --- |
| start / layer_id[3:0] | 输入 | 时钟上升沿 `start && start_ready` 时接受；同时锁存层编号；有效编号 0—11 |
| task_shift[5:0] | 输入 | 与start一同提交，只在任务接受时锁存，范围0—63 |
| active_shift[5:0] | 输出 | 联合顶层锁存的右移量；忙时改外部配置不会影响当前任务 |
| start_ready | 输出 | 仅空闲为 1；C 应以此判断能否发新任务 |
| busy | 输出 | 从接受正常任务后持续至成功或失败；`!busy` 不一定等于可接受新任务 |
| start_rejected | 输出 | 非 ready 时遇到 start 的指示，重复启动不会更改当前任务 |
| active_layer | 输出 | 锁存的层编号，在该任务期间保持稳定 |
| done | 输出 | 全部输出写回响应成功后产生一拍脉冲 |
| error / error_code | 输出 | 错误时产生一拍 error；error_code 保持至下次接受任务或复位 |
| completed_outputs | 输出 | 已收到成功写确认的输出数量，新任务清零 |
| task_cycles | 输出 | B 内部任务周期计数，用于调试；不包含启动之前平台装载/调度，不能直接当作官方端到端周期 |

`start` 应为单拍命令；若持续拉高到下一次 ready，会被当作另一任务。CSR 中的粘滞完成位/中断等由 C 适配。

错误码：1 外部访存响应错误；2 非法层编号；3 运算端错误；4 内部缓冲地址/端口冲突；5 控制状态异常。错误不同时报告成功。当前无超时恢复硬件，外部永久不响应时需系统复位。

## 4. A/B 内部运算适配

下表是 B 调度器与适配器之间的内部契约；使用联合顶层时，C 无需接这些端口。适配器转接 A 的 in_valid/in_ready、in_x/in_w/in_bias/in_shift、out_valid/out_ready/out_data。

| 端口 | 方向 | 规则 |
| --- | --- | --- |
| mac_clear | 输出 | 非计算阶段或复位期间清空运算端的累加、元数据、未完成响应和错误状态 |
| mac_in_valid / mac_in_ready | 输出/输入 | 同拍均为 1 才接受一对操作数 |
| mac_x / mac_w | 输出 | DATA_W 位原始编码；暂停时保持 |
| mac_bias | 输出 | 当前列的 BIAS_W 位偏置编码，在整个点积期间保持 |
| mac_first / mac_last | 输出 | 随操作数握手，标记该点积第一项/最后一项；INNER=1 时二者同时为 1 |
| mac_out_valid / mac_out_ready | 输入/输出 | 同拍均为 1 接收一个结果；A 在等待期间保持结果 |
| mac_result | 输入 | 16位原始编码，包含 A 负责的偏置、舍入及饱和 |
| mac_error | 输入 | 适配器检测到点积边界等协议错误时置位；B终止任务并清空计算端 |

每个结果依次送入 INNER 对数，期间可反压；一组输入完成后等待一个结果，不交错多个点积。B 依次计算行 i、列 j：`X[i,k]` 与 `W[k,j]`，k 从 0 至 INNER−1。

A 的 lane 固定每64次输入握手形成一个点积，无first/last/clear/error端口。适配器检查首尾标记与64次计数，锁存首对输入的bias/shift，只允许一个点积及结果在途；等待输出时不接受下一组。

适配器将mac_clear先寄存，再控制lane局部复位，释放经两级时钟同步；没有把组合状态译码直接接到A的异步复位。清空和局部复位期间屏蔽输入/输出握手，整体清除A的计数、偏置、shift和待取结果。错误保持到clear或全局复位。C仍须负责系统级复位释放与旧访存响应清除。结果延迟由握手决定，不能固定等待若干拍。

## 5. B/C 逻辑访存端

所有请求字段在 `valid && !ready` 时保持。**仅允许一笔未完成事务**。每笔读或写都必须返回一笔响应，响应需保持至 `rsp_ready`；零延迟准备好响应也应遵守该保持要求。

| 端口 | 方向 | 含义 |
| --- | --- | --- |
| mem_req_valid / mem_req_ready | 输出/输入 | 请求握手 |
| mem_req_write | 输出 | 0 读，1 写；当前仅向 Y 写入 |
| mem_req_tensor[1:0] | 输出 | 0=X，1=W，2=b，3=Y |
| mem_req_index[31:0] | 输出 | 所选张量中的**元素序号**，不是字节地址 |
| mem_req_wdata | 输出 | 写数据放低 RESULT_W 位，其余位补零 |
| mem_rsp_valid / mem_rsp_ready | 输入/输出 | 响应握手；写响应必须表示实际写回已经完成 |
| mem_rsp_rdata | 输入 | 读数据放对应编码的低位；X/W 低 DATA_W 位，偏置低 BIAS_W 位 |
| mem_rsp_error | 输入 | 对应事务失败；读错误的数据不进入缓存，写错误不计完成 |

元素顺序：X 行优先 `i*INNER+k`；W 按数学形状 INNER×COLS 行优先 `k*COLS+j`；b 为 j；Y 行优先 `i*COLS+j`。编码文件每行一个元素的十六进制补码。**这不是对实际平台内存的打包/字节序承诺**；C 需与 A/B 确定其到真实内存的映射。

A交接包的候选二进制布局为小端：X/W/Y每元素2字节，bias由signed40符号扩展到8字节容器。联合顶层的Y编码放低16位、高位补零，C按2字节元素写入；不能把负数的零扩展逻辑载荷误当作64位有符号Y。bias读取取容器低40位。物理基址、字节使能和寄存器由C依据官方平台确认。

每个任务全量装载 W 和 b，再逐行装入 X，计算本行所有输出。每个输出写回并获得确认后，再计算下一个。新任务重新装载全部参数，不跨任务使用旧权重或旧输入。

## 6. 缓冲与 SRAM

`tensor_buffer` 把逻辑宽字拆成 16 位通道，按深度分 bank。默认配置：

| 缓冲 | 有效逻辑容量 | 行为后端的宏形状数量 |
| --- | --- | --- |
| 当前 X 行 | 64×16 bits | 1 个 16×128 |
| 全层 W | 16384×16 bits | 4 个 16×4096 |
| 全层 b | 256×40 bits，分为 3 个 16 位通道 | 6 个 16×128 |

共 4 个大宏、7 个小宏，物理存储位容量 276,480 bits（33.75 KiB），不含接口寄存器。**这是按形状统计的存储容量，不是面积或功耗测量，也不保证 2.25 mm² 达标。** 修改数值宽度会改变通道和宏数量。

默认 `sram_wrapper` 是可移植同步行为模型：单端口；写周期不更新读输出；不复位整个阵列。缓冲层在复位期间屏蔽读写访问，并清除 rd_valid；阵列原有内容保留。缓冲层提供 rd_valid，控制器等待数据有效，读写冲突被视为控制错误。

顶层保留完整 32 位缓冲地址，再检查是否越界，避免高位被截断后误访问合法单元。仿真时检查缓冲地址宽度能否表示全部逻辑深度、SRAM 地址宽度是否与宏深度一致；非法参数会使测试失败。

正式替换时定义 `B_USE_OFFICIAL_SRAM`，并提供 `b_official_sram_16x128/1024/4096` 中实际用到的适配模块。模板接口是 clk/en/we/addr/wdata/rdata；需按真实宏极性、端口、延迟和工艺视图实现。未提供适配模块时编译失败，避免误把行为模型当官方宏。

当前缓冲 rd_valid 按一拍同步读产生；若官方宏的外部读延迟不同，先修改该有效信号/选 bank 延迟并复测。控制器可独立等待 X/W 数据有效。

## 7. 与团队最终实现衔接前要确认

1. 团队确认采用 A_work 当前数值契约及适配层；后续修改配置或接口必须重新生成数据并复测。
2. C 的物理访问方式、基地址、步长、打包、错误和写完成语义。
3. 官方 SRAM 宏名/端口/延迟及标准单元库、综合工具与有效约束。
4. 复位时由 C 清除旧访存响应，由 A 清除旧结果；本原型不靠任务间清空 SRAM 阵列来掩盖错误。

本地验证使用A正式RTL、外部数据与B调度；C访存和SRAM仍为仿真后端。十二层按三组、每组四层连续运行，控制故障和复位恢复另以抽样矩阵覆盖。有效结果见本次回归摘要，不能等同于官方SoC、宏、综合或统一精度评测通过。
